# Temporal semantics: stutter, regular patterns, and fairness

Design discussion summary, not a normative API specification. The proposed
operator names and compositional fairness surface below are not implemented.
Existing behavior is called out separately. Refinement is outside this note.

## 1. States, configurations, and behaviors

A graph node is a configuration `C = (S, K)`: domain state plus control state.
An edge is `(S, K) --a--> (S', K')`, where `a` identifies the generating action.
Control determines the available transitions; an action label is not itself the
entire control state.

`Changed` compares domain states under model-state equality, not configuration
identity. A real edge can change only control, or be a complete no-op. "Real"
means generated by the model, not necessarily state-changing.

The checker completes genuine terminals with synthetic stuttering so temporal
formulas have infinite behaviors. It does not add idle edges at every node.
An unexplored bounded frontier is not a terminal; missing successors must not
be treated as proof of termination or disabledness.

## 2. Temporal operators: make the argument interpretation explicit

Distinguish a state predicate `p(S)` from a transition predicate `r(S, S')`.
They are not interchangeable, even on a behavior whose domain state is constant.

Proposed default surface, with `F` = eventually, `G` = always, and
`U` = unchanged domain state:

| Operator | Meaning |
|---|---|
| `Eventually(p)` | `F p` |
| `Always(p)` | `G p` |
| `EventuallyOccurs(r)` | `F (Changed AND r)` |
| `AlwaysOnChange(r)` | `G (U OR r)` |

Ordinary Always/Eventually accept state predicates or already-formed temporal
formulas. Bare transition predicates should require the explicit on-change
operators, or an explicitly stutter-sensitive surface for literal `G r` / `F r`.
Do not invent a different ordinary F/G semantics for a constant tail.

On a constant terminal behavior, `AlwaysOnChange(r)` is vacuously true and
`EventuallyOccurs(r)` is false. This does not contradict
`Always(phi) => Eventually(phi)`: the two specialized operators apply different
guards to the raw relation. Ordinary F/G retain their usual meaning for a fixed
formula, including `phi = EventuallyOccurs(r)`.

Negation remains ordinary:

```text
NOT AlwaysOnChange(r)   = EventuallyOccurs(NOT r)
NOT EventuallyOccurs(r) = AlwaysOnChange(NOT r)
```

In particular, forbidding an occurrence is not requiring a negated occurrence.

**Current implementation:** the default transition overloads still use the
names `Always` and `Eventually`, with these role-dependent guards. The proposed
names clarify that existing interpretation rather than changing the lowering.
Accepting some asymmetry between state-based F/G and transition-based regular
patterns is preferable to silently reinterpreting their arguments.

## 3. Stutter-invariant regular patterns

Safe regex letters describe **changing transitions**. For a finite physical
transition word `w`, let `h(w)` delete domain-unchanged steps. A pattern with
visible language `L` matches exactly when `h(w)` belongs to `L`; its physical
language is the inverse image `h^-1(L)`.

This is a semantic definition, not a requirement to erase a trace first.
The lowered pattern consumes unchanged steps on the fly without counting them.
Invariance is relative to full domain-state equality, not merely equality of
the propositions mentioned by a particular pattern.

Writing `Lift(R)` for that lowering, with `C` denoting changing steps:

| Visible pattern | Physical lowering |
|---|---|
| Empty language | Empty language |
| Epsilon | `U*` |
| Atom `r` | `U* . (C AND r) . U*` |
| Concatenation `R . T` | `Lift(R) . Lift(T)` |
| Union, intersection, complement | Same Boolean operation on lowered languages |
| `R*` | `U* UNION Lift(R)*` |
| `R+` | `Lift(R) . Lift(R*)` |
| Optional `R` | `Lift(R) UNION U*` |

Complement is relative to all visible changing-step words before lowering, and
all physical words afterward. The extra `U*` in the star case matters: zero
visible repetitions must match an all-unchanged physical word.

A state-predicate letter `p(S)` needs the same treatment; it is evaluated at the
source of a changing transition. Merely using state predicates does not make
ordinary positional concatenation or repetition stutter-invariant.

`After(R, phi)` existentially selects a matching prefix and checks its suffix;
`Whenever(R, phi)` checks every matching-prefix suffix. Matching is anchored,
not an implicit search anywhere. Physical-position fusion/overlap are excluded
from the current safe surface. Sharing a *visible* step could be specified
separately; it is not fundamentally impossible.

**Current implementation:** `SafeRegex` already implements this visible-word
model and lowering.

## 4. Fairness selects transitions, then constrains behaviors

A fairness selector may inspect `a`, `(S, S')`, or `(S, a, S')`. These can select
different families: two parallel edges may have identical state effects but
different action labels. Labels alone need not imply the desired progress.

First fix a uniform occurrence policy. Historical fairness counts only
domain-changing edges; explicit semantic-action fairness can count selected
real neutral edges. Synthetic terminal completion never counts. Use the same
policy on both sides:

```text
E_q(C) = some eligible outgoing edge from exact configuration C satisfies q
T_q(e) = the traversed edge is eligible and satisfies q

WF(q) = (F G E_q) implies (G F T_q)
SF(q) = (G F E_q) implies (G F T_q)
```

Enabledness examines available edges, not just the edge taken. Equal domain
states can have different enabledness because their control differs. Fairness
does not force a prerequisite action merely because q could become enabled later.

Strong fairness implies weak fairness for the same selection and grouping.
Weak fairness can admit an action that is repeatedly enabled and disabled but
never taken; strong fairness rejects that behavior. Neither forces an
opportunity enabled only finitely often. Neither bounds finite waiting, nor
does fair no-op activity automatically establish domain progress.

### A compositional core, rather than special cases

Proposed core: `WF(q)`, `SF(q)`, Boolean constants, AND, OR, and NOT.
Keep Boolean operations on edge predicates distinct from those on fairness
formulas:

| Requirement | Expression |
|---|---|
| One collective weak obligation | `WF(qA OR qB)` |
| Separate weak obligations | `WF(qA) AND WF(qB)` |
| At least one individual obligation holds | `WF(qA) OR WF(qB)` |
| Violation of weak fairness | `NOT WF(q)` |

Analogous constructions use SF. `NOT WF(q)` is not `WF(NOT q)`, strong fairness,
or merely the absence of an assumption: it requires an unfair behavior.

For finite known keys, define `q_k(e) = q(e) AND identity(e) == k`.
Then Each is convenient sugar, not a distinct fairness semantics:

```text
WeakEach:    AND over k: WF(q_k)
StrongEach:  AND over k: SF(q_k)
Some fair:   OR  over k: WF(q_k)
Collective:  WF(OR over k: q_k)
Per group:   AND over g: WF(OR over k in Members(g): q_k)
```

One occurrence can discharge only its own keyed obligation. A fair member need
not actually run: permanent disabledness can satisfy fairness vacuously.
Collective weak fairness and separate weak fairness are not generally ordered:
alternating members can keep the union continuously enabled while neither
member is continuously enabled.

Unknown/discovered key sets require an explicit domain policy; unbounded
quantification is not generally replaceable by a finite Boolean expansion.

**Current implementation:** `Fairness` is passed separately to checking and
combines obligations conjunctively via `+`. It has Action/Each helpers, but not
a first-class WF/SF formula surface with arbitrary Boolean composition.
Historical step selectors create separate obligations by step-function ID;
historical relation selectors create collective obligations. This should not
be confused with a uniform future formula API.

### TLA+ parallels and boundaries

| Our intended requirement | TLA+ |
|---|---|
| Collective weak / strong | `WF_vars(A \/ B)` / `SF_vars(A \/ B)` |
| Separate weak / strong | `WF_vars(A) /\ WF_vars(B)` / `SF_vars(A) /\ SF_vars(B)` |
| Each key weak / strong | `\A k \in Keys : WF_vars(Action(k))` / corresponding SF |

TLA+ actions are transition formulas, not independent edge tags.
`ENABLED A` is the state predicate "some next-state assignment satisfies A";
it does not automatically conjoin a separately defined Next relation.
Fairness uses `ENABLED <<A>>_vars`, where
`<<A>>_vars = A AND vars' != vars`. Thus counting real neutral edges is not
automatically equivalent to TLA+ fairness for a domain-only tuple.

`WF_vars(ENABLED A)` does not mean fairness of A: its occurrence can be any
vars-changing step from an A-enabled state. Also, the common
`Init /\ [][Next]_vars` admits stuttering throughout, unlike terminal-only
completion of Accordant's exact graph.

## 5. Fairness formulas and possible RLTL integration

At minimum, introduce compositional fairness expressions with clear semantics.
Whether to expose them directly as RLTL formulas, through a separate formula
type, or through both views remains a design choice.

WF/SF need only RLTL's LTL fragment:

```text
WF(q) = G F (NOT E_q OR T_q)
SF(q) = F G (NOT E_q) OR G F T_q
```

Enabledness cannot be recovered from q's truth values on the executed trace:
the same trace can ignore an available q edge or have no such edge available.
The graph supplies E_q; transition evaluation supplies T_q.

For fairness expression `Fair` and property `Phi`, check `Fair implies Phi`.
The ordinary negated-property construction then searches for
`Fair AND NOT Phi`. Do not also apply an unintended separate fairness filter.

| Approach | Benefits | Costs / cautions |
|---|---|---|
| Separate compositional fairness formula | Explicit assumptions, policy, and diagnostics; permits specialized algorithms | Arbitrary OR/NOT require more than the current conjunctive obligation checker |
| Lower WF/SF into RLTL | Reuses Boolean composition and the existing automaton/product pipeline; works with RLTL properties | Automata may grow; fairness-specific diagnostics/optimizations need preservation |

A reasonable initial design is a small fairness-expression surface with an
RLTL lowering as its semantic reference, retaining specialized algorithms only
where equivalence is established. No new temporal WF/SF primitive is necessary.

Existing infrastructure includes exact-node cached `Enabledness`,
`StateProp.Enabled` / `EnabledAction`, transition-aware atoms, and
`SymbolicRltlCheck`. Reuse it with matching enabledness/occurrence policies,
raw RLTL temporal composition rather than accidental double lifting, and
frontier-aware evaluation.

No-X syntax alone does not establish invariance under domain-state stuttering:
enabledness observes control-dependent availability, and action occurrences
carry information beyond S. State that richer observation contract explicitly.
Also check for empty admitted behavior sets: contradictory fairness assumptions
can make every property hold vacuously.
